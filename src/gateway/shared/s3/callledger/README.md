# Local ledger and pricing foundation

`Ledger(db_path, authority=..., price_snapshot=..., trusted_bounds=..., trusted_requests=...)` implements SQLite-authoritative accounting. It never opens a provider connection. Caller-owned paths, authority and registries are trusted-process inputs. Each operation requires explicit context and caller limits. Snapshot paths are passed to `load_snapshot`; no workspace or global configuration is searched.

## Admission and settlement

1. `admit_operation(plan, context=..., limits=..., mode=...)` atomically funds every child, retry and conditional branch, including cumulative attempted-dispatch quota. The immutable authority definition is checked when reopening. Changing run IDs does not reset its counters or liabilities. Reusing an operation ID is idempotent only with the same plan/context/limits/mode.
2. `begin_attempt(allocation, context=..., request=...)` transfers a funded child hold to an active attempt and consumes its quota before the caller sends anything. Context, purpose, allocation, shape, policy and exact registered request evidence are checked. A crash after this commit is ambiguous even if transport never occurred: the reservation stays held. The ledger does not automatically redispatch.
3. `settle(attempt_id, metadata=..., usage=...)` computes indicative Decimal cost from the original pinned policy. The allowlisted usage projection must bind the normalized billed usage and its digest. Missing billed components retain the entire reservation as unknown liability. Invalid/refused attempts are still accounted. An identical settlement is idempotent; a different settlement conflicts. An unknown settlement is conservative and immutable in this edition; reconciliation needs a separately designed protocol.
4. `finish_child` releases only unused future holds with a matching settlement or database-verifiable no-dispatch proof. An active attempt cannot be released or declared skipped. Complete requires an accounted successful result, while failed/unknown children leave the operation partial. This is accounting completion, not a domain task pass.

Known spend, future holds, active holds and unknown liabilities are distinct categories. A transferred reservation is never counted twice. A reported charge above its evidenced bound is recorded without clamping and halts further funding/dispatch; such a breach can exceed the configured cap and must be surfaced. Caller software must obtain conservative, applicable bounds before transport. This library cannot promise a provider invoice will obey an incorrect bound.

UTC operation deadlines persist. In-process monotonic elapsed time can only tighten them; backward wall-clock movement refuses new funding/dispatch. Settlement remains allowed after expiration, halt or clock rollback. `retry_fits` checks backoff headroom without sleeping or dispatching. Actual SDK retries, cancellation, per-attempt transport timeout, streaming and all token counting remain future controller/driver responsibilities.

## Evidence and synthetic fixtures

Funding and request schemas alone do not establish token or price proof. Exact entries must be present in caller-supplied trusted registries and bind the snapshot/policy/provider/model/shape/request hashes and count maxima. That caller must actually verify the evidence. The `simulation` mode supports authored synthetic accounting fixtures. `external` accounting refuses synthetic snapshots/bounds; its metadata validation does not authenticate a primary source, grant API access or prove an actual driver sent the bound request. No external price or token proof is established by this repository's synthetic tests.

`PricePolicy` prices inclusive input once, splitting uncached/read/write components only for a declared partitioned policy. Inclusive output already contains reasoning; it is not added again. Unbilled null output stays null. Missing positively billed usage or unknown fee context yields unknown total cost. Zero rates can produce known zero cost without inventing token counts. Arithmetic refuses token counts above 40 decimal digits rather than rounding silently. Computed indicative price is separate from invoice/fee/refund proof.

Snapshots have explicit synthetic versus verified-primary metadata, a data hash and exact provider/model/context lookup. A primary web source may have a null source commit; no fabricated commit is required. Verification/freshness/effective dates and provider access remain the trusted caller's responsibility. The committed price fixture is entirely synthetic. `scripts/update_prices.py source destination` validates and writes a new snapshot; it makes no network request and refuses overwrite.

## Durability, projection and privacy

Short `BEGIN IMMEDIATE` transactions, SQLite WAL and `synchronous=FULL` serialize funding and commit events with their outbox rows. SQLite is authoritative; JSONL is a disposable projection. `export_jsonl(path)` serializes exporters, verifies event hashes, fsyncs a temporary file, atomically replaces the projection and marks its outbox. If replacement or marking fails, a later export rebuilds exact ordered content from SQLite. It never imports projection data into the ledger. Projection output cannot replace the database or its WAL/SHM/journal. There is no background projection process or unbounded stress campaign.

Raw provider payloads do not enter the store. `project_usage` retains only approved nonnegative integer/null fields and marks discarded values. Persistent metadata includes closed status/error codes, numeric usage, trusted identifiers/digests, declared rates and safe source metadata. It excludes prompts, responses, image paths, headers and exception bodies. Pydantic exception strings hide inputs; callers must not serialize `ValidationError.errors()`, which can contain them. Trusted identifiers must be opaque IDs, not payload text. The library does not establish filesystem containment against hostile callers or file replacement attacks.

`record_reuse` accounts a caller's network-free lookup with matching registered request/context/capture provenance. Current external cost is zero, original source cost remains separately known or unknown, and no attempt is added. It does not load or create a cache payload. `record_non_model` records local spans with null inference tokens and separately unknown/supplied resource cost; no free-runtime inference is made.

For detached use, copy this complete subpackage beside the provider models under a consumer-owned `shared` package, plus LICENSE and source-file/commit receipts. Dependencies remain Python 3.12, stdlib and Pydantic. Databases, live configuration, secrets and owner test artifacts must not be copied. Consumer vendoring and actual controller conformance require separate admission.
